# Task/checklist drafts and Engineer pin controls

Implemented and checked on 2026-11-06 (Asia/Manila).

- Task and QC checklist forms persist unfinished fields synchronously in browser storage. Drafts are scoped to account, project/company library and the specific pin/task/checklist; creating and editing have separate keys. Close retains work, Discard draft confirms removal, and confirmed server saves clear only the matching draft revision. An older save cannot clear a newer draft. Refresh failure after a committed save does not report that the task/checklist was unsaved or resurrect its draft.
- Drafts retain incomplete entries, all criteria, order, measurements, references and cited standards. Task drafts also retain the copied-checklist selection. Task-specific Engineer inspection photos remain optional; company/project QC drafts preserve their Photo required setting. No incomplete task/checklist is automatically created on the server.
- Shared browser-draft storage retains an in-app fallback if storage fails and warns before browser exit while such work remains. Persistence is on the same browser/device; clearing browser data removes persisted drafts. No cloud synchronization or historical QA rewrite is introduced. Existing task-draft keys and format remain compatible.
- QC Add item appears after the list, beneath the newest item. Adding an item focuses and scrolls to its text field. Reordering/removing items is included in draft saving; the existing 60-item maximum remains enforced.
- Engineers with Assigned work access can use Move pin from the pin panel, context menu or quick actions, then click/tap the new position. Select-drag remains available. Cancellation, stale access/lock checks, coordinate-only saves, rollback and undo/redo are covered. The latest revision and existing backend permissions still apply. Pin location remains QA evidence, so movement after submission can require resubmission; the editor explains this.
