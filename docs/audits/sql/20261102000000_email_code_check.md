# Check an emailed code without using it

| Field | Value |
|---|---|
| File | `supabase/migrations/20261102000000_email_code_check.sql` |
| Applied | 2026-11-02 via the connector, live version `20261102012618`, verified (service role only) |
| Dependencies | `20261101210000_email_verification_and_codes` (`email_codes`) |
| Reversible | Yes: `drop function public.check_email_code(text, text, text)`. Additive, no table or column changes |

| Object | Effect |
|---|---|
| `check_email_code(email, purpose, hash)` | Same rules as `consume_email_code` (newest unused unexpired code, 5 wrong tries then locked, wrong tries counted) but a right code is NOT marked used. Lets the Forgot password screen confirm the code on its own step before the new-password step; `verify_reset` still consumes it, so a code is never usable twice. |

## Verification queries (read-only)

       has_function_privilege('service_role','public.check_email_code(text,text,text)','execute') svc;
-- expected: false, false, true
