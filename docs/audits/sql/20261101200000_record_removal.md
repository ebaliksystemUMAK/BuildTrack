# Super Admin record removal

| Field | Value |
|---|---|
| File | `supabase/migrations/20261101200000_record_removal.sql` |
| Applied | 2026-11-01 via the connector, live version `20261101111602`, verified |
| Dependencies | `20261101180000_project_recycle_bin` (`project_is_removed`), `is_super_admin()`, `display_name()` |
| Reversible | Yes, rollback block at the end of the file. Nothing is deleted or rewritten by the migration |

| Object | Effect |
|---|---|
| `removed_at / removed_by / removed_reason` on `daily_reports`, `site_issue_reports`, `client_snags` | Null for every record today; reason 5-300 characters. |
| Eight restrictive SELECT policies | Hide a removed record and its photos / history from everyone. Restrictive policies only narrow what the existing ones allow. |
| `*_guard_removal` triggers | The three columns change only through the functions below for signed-in accounts; the SQL editor / service role are not restricted. |
| `record_is_removed`, `site_photo_is_removed` | Used by the policies. |
| `record_info` | Internal. |
| `search_removable_records`, `preview_record_removal`, `remove_record`, `restore_record`, `get_removed_records` | Super Admin with the authenticator only (`is_super_admin()`). `remove_record` needs a reason and the exact typed phrase; audited as `record.removed` / `record.restored`. |

## Verification queries (read-only)
```sql
select count(*) filter (where removed_at is not null) from public.daily_reports;     -- expected 0 (same for site_issue_reports, client_snags)
select tgname, tgrelid::regclass from pg_trigger where not tgisinternal and tgname like '%guard_removal';
select tablename, policyname from pg_policies where schemaname = 'public' and policyname like 'removed %' order by 1;
select p.proname, has_function_privilege('anon', p.oid, 'execute') anon, has_function_privilege('authenticated', p.oid, 'execute') auth
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace where n.nspname = 'public'
   and p.proname in ('remove_record','restore_record','get_removed_records','search_removable_records','preview_record_removal','record_info');
-- expected: anon false everywhere; auth true except record_info
```

## If a removed record must come back and the screen is unavailable (owner, SQL editor)
```sql
update public.daily_reports set removed_at = null, removed_by = null, removed_reason = null where id = '<id>';   -- or site_issue_reports / client_snags
```
